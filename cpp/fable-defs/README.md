# fable-defs-cpp

A C++ package for [Fable: The Lost Chapters](https://en.wikipedia.org/wiki/Fable_(2004_video_game))'s
definition classes and data types.

The declarations were recovered once from the game's debug-build PDB with
`decomp-cli` from `fable-decomp-engine` (`~/git/fable-decomp-engine`), cleaned,
and are now maintained here as ordinary C++ source. The generator is not part
of this package; it lives in `tools/fable-defs-bootstrap` as a one-time
bootstrap tool.

The result uses the game's original class, member and enum names:

```cpp
namespace fable { namespace defs {

class CCreatureDef {
public:
    std::shared_ptr<CWoundMorphs> PWoundMorphs;
    ...
    std::vector<std::int32_t> InitialActions;
    std::map<std::string, std::int32_t> PhonemeAnim;
    std::int32_t Inventory;
    CDefString BattleCrySound;
    ...
};

} }
```

## Layout

```
include/fable/defs.hpp              umbrella header
include/fable/defs/base.hpp         CDefString, CDefIndex
include/fable/defs/fwd.hpp          forward declarations for every class
include/fable/defs/enums.hpp        98 enums with their original symbols
include/fable/defs/classes.hpp      345 classes/structs (286 def classes + dependencies)
include/fable/defs/visit.hpp        generated field reflection (`visit_fields`)
include/fable/defs/transfer.hpp     generated Transfer metadata: exact wire names,
                                    member paths, defaults, `visit_transfer_fields`
tests/defs_test.cpp                 compile-time and trivial runtime checks
```

The package is header-only. `fable::defs` is the namespace; original inner
namespaces are preserved (`fable::defs::NUISystem::CUIDef`).

## Wire metadata

`transfer.hpp` is generated from the decompiler's lifted `Transfer` bodies
(`decomp-cli lift '<Class>::Transfer'`). It records the authoritative wire field
list:

- exact wire name (`PositionX` maps to `Position.X`)
- member path
- transfer kind (value, vector, map, subcomponent, object)
- explicit default values

It provides `visit_transfer_fields(object, visitor)`, `visit_model_fields`
(transfer metadata when available, reflection otherwise), and
`apply_model_defaults(object)`.

This is what lets text fields such as `PositionX` lower into the model's
`Position.X`, and lets the wire layer write the correct control names.

`visit.hpp` provides a generated `visit_fields(object, visitor)` overload for
every model class. The visitor receives each field's wire name and a mutable
reference (or a `detail::BitfieldRef` for bit-fields), including inherited
fields. It is generated by `tools/gen_model_visit.py` and used by the compiler
lowering layer.

```cpp
#include <fable/defs/visit.hpp>

struct Visitor {
    template <class T> void operator()(const char *name, T &field) { /* ... */ }
    template <class T>
    void operator()(const char *name, fable::defs::detail::BitfieldRef<T> field) { /* ... */ }
};

fable::defs::CCreatureDef value;
fable::defs::visit_fields(value, Visitor{});
```

## Use

With CMake:

```cmake
add_subdirectory(path/to/fable-defs)
target_link_libraries(my-target PRIVATE fable::defs)
```

or, after installing:

```cmake
find_package(fable-defs REQUIRED)
target_link_libraries(my-target PRIVATE fable::defs)
```

Then:

```cpp
#include <fable/defs.hpp>

fable::defs::CCreatureDef creature;
creature.InitialActions.push_back(1);
```

Manual use is just `-I path/to/fable-defs/include`.

## Type policy

The original PDB declarations use MSVC spellings and the game's own containers.
This package normalizes them:

| PDB declaration | Package |
|---|---|
| `long` / `unsigned long` / `int` | `std::int32_t` / `std::uint32_t` |
| `std::vector<T,std::allocator<T>>` | `std::vector<T>` |
| `std::map<K,V,std::less<K>,std::allocator<…>>` | `std::map<K,V>` |
| `CCharString` | `std::string` |
| `CWideString` | `std::u16string` |
| `CCountedPointer<T>` | `std::shared_ptr<T>` |
| `CArray<T>` | `std::vector<T>` |
| `CVectorMap<K,V,Cmp>` | `std::vector<std::pair<K,V>>` |
| `CDefPointer<T>` | `T *` |
| `CDefString` / `CDefIndex` | small `std::int32_t` wrappers |
| enums | `enum E : std::int32_t` |

Methods, constructors, statics and runtime bases (`CDefClassBase` and friends)
are removed. Data-bearing bases such as `CThingBaseDef` and
`CCombatAbilityData` are kept. All fields are public and in declaration order.

## What this is not

- **Not a wire format.** A def body on disk is a sequence of
  `(uint32_t crc32(field name), value)` controls. Do not `memcpy` these classes
  onto the wire.
- **Not ABI-compatible with the retail engine.** Dropping methods and runtime
  bases changes layout. The structure is for reading, tooling and code
  generation, not binary interop.
- **Not a behavioral reimplementation.** The standard-container substitutions
  (`std::string`, `std::shared_ptr`, `std::vector`) do not reproduce the
  original methods or comparison semantics.

## Building and testing

From the repository root:

```bash
cmake --preset debug
cmake --build --preset debug
ctest --preset debug
```

Or build this package alone:

```bash
cmake -S cpp/fable-defs -B /tmp/fable-defs-build
cmake --build /tmp/fable-defs-build
ctest --test-dir /tmp/fable-defs-build
```

The header compiles as C++11 or later.

## Regenerating from scratch

The bootstrap tool is optional and needs the proprietary debug PDB:

```bash
cargo run --manifest-path tools/fable-defs-bootstrap/Cargo.toml -- \
  --decomp-cli ~/git/fable-decomp-engine/target/release/decomp-cli
```

It writes a single cleaned header to `tools/fable-defs-bootstrap/out/`. The
curated package is intentionally not regenerated automatically.
